Hack LoRa & read I2C with the badge's Bus Pirate

The badge's Bus Pirate build turns it into a pocket protocol workbench. We'll scan an I2C bus and read a real sensor, then send and sniff LoRa on the air — including making the badge talk to a live Meshtastic node — and point out the badge-specific tweaks and the one connector that will bite you.

DEF CON Badge Bus Pirate I2C LoRa ·intermediate·~25 min·updated 2026-07-31

The ESP32 Bus Pirate (geo-tp / KonradIT) is a Bus Pirate–style multitool: one CLI that speaks I2C, SPI, UART, 1-Wire, and more, with Wi-Fi/BLE scanners and radio tools bolted on. We ported it to the badge so it runs on the 2.4″ TFT with the d-pad, and taught it to drive the badge's SX1276 LoRa radio. This guide covers scanning a bus, reading a sensor, and putting real LoRa on the air.

!! authorized use only This build is transmit- and attack-capable (Wi-Fi deauth/sniff, BLE spoof, LoRa/Sub-GHz transmit, bus/RF jam). Only point it at hardware, networks, and RF you own or are explicitly authorized to test. The flasher asks you to confirm this before it writes the image.

What you'll need

  • A ScriptKitty badge with the 915 MHz antenna attached (never TX without it — you can cook the radio's PA).
  • A USB-C cable and a Chromium browser (Chrome/Edge) for the in-browser flasher and serial console.
  • For the I2C demo: any 3.3 V I2C sensor. We use a BME280 (temp/humidity/pressure), but a display or any breakout works.
  • For the LoRa demo: ideally a second badge (or any Meshtastic node) within a few meters.
  • A few jumper wires. Read the connector warning below before you plug anything in.

1 — Flash the Bus Pirate build

Open the flasher, pick ESP32 Bus Pirate from the dropdown, and flash it over Web Serial. It's a complete factory image written at 0x0 — no other steps.

→ open the flasher (ESP32 Bus Pirate)

// how you'll talk to it The Bus Pirate exposes the same CLI three ways: USB serial (the serial monitor on this site, 115200 baud), a Wi-Fi web UI (it hosts an AP named ESP32-Bit-Pirate, password readytoboard, at 192.168.4.1), and directly on the badge screen with the d-pad. This guide uses the USB serial console — connect, and you'll get the banner and a > prompt. Type help anytime.

2 — Wire I2C to the QWIIC connector

Wire the sensor to the badge's QWIIC / I2C connector, matching each lead to the silkscreen label next to it — 3.3V, GND, SDA, SCL — as in the photo below. The badge routes that connector to its I2C bus (SDA on GPIO 35, SCL on GPIO 36).

3.3VVCC / 3V3—
GNDGND—

!! match the silkscreen, and meter it first Wire to the printed labels one lead at a time — don't assume a pre-made keyed QWIIC cable lands power and ground where this board expects them. Before you connect the sensor, meter 3.3V against GND to confirm the rail, so a swapped lead can't cook the board or the sensor.

3 — Scan the bus and read a register

In the serial console, drop into I2C mode and scan. The badge Bus Pirate also paints the scan on the TFT, so you get results on-screen and over serial at once.

> mode i2c
i2c> scan
Scanning 0x08..0x77 ...
  found: 0x76
1 device(s)

0x76 is the BME280's default address. Confirm the chip by reading its ID register (0xD0) — a BME280 returns 0x60:

i2c> read 0x76 0xD0 1
0x76 [0xD0] -> 0x60   # 0x60 = BME280
// what you just proved A clean scan → 0x76 and chip-id 0x60 is the end-to-end "the bus works" check. From here the same read/write commands talk to any I2C target — EEPROMs, displays, sensors, another MCU pretending to be a peripheral.

4 — Send and sniff LoRa

This is the headline feature we added: the upstream project ships an SX126x driver, but the badge's radio is an RFM95W (SX1276), so we wrote a dedicated SX127x driver for it. Core radio ops — send, receive, sniff, RSSI, set-frequency, airtime — run clean.

!! antenna on, every time Attach the 915 MHz antenna before any transmit (send, spam, jam, mesh). Transmitting into no antenna stresses the SX1276 power amp.

Badge → badge

On the receiver badge, drop into LoRa mode and listen:

> mode lora
lora> receive

On the sender badge, transmit a payload:

lora> send RXTEST-from-badge-A

The sender reports TxDone plus airtime; the receiver prints the payload with signal stats. In our bench runs, badge-to-badge at close range read about RSSI −57 to −81 dBm, SNR ~13 dB — a solid link.

lora> RX "RXTEST-from-badge-A"  rssi=-57 dBm  snr=13.0 dB

Waterfall — see the band

Sweep the spectrum and watch it paint as a heat map (blue → red) on the TFT:

lora> waterfall
// a tweak worth knowing The radio and the display share one SPI bus on the badge. Naively reading RSSI and drawing to the screen on every point deadlocks the board — so the badge build batches a whole sweep on the radio, hands the bus back to the display once, then paints all the rows. If you fork this, keep radio ops and TFT draws from interleaving on the shared bus.

5 — Talk to a real Meshtastic node

The badge Bus Pirate's mesh sub-shell speaks real Meshtastic, so you can transmit a text that pops up on any Meshtastic node or phone nearby. The defaults don't match a stock US node out of the box — set these three first:

SettingValueWhy
presetLONG_FAST= BW250 / SF11 / CR4:5
frequency906.875 MHzUS LongFast default — must set manually
keyAQ==the default public channel PSK (not preloaded)
 
> mode mesh
mesh> 2   # preset  -> LONG_FAST
mesh> 3   # setfreq -> 906.875
mesh> 4   # setkey  -> AQ==
mesh> 6   # send-text -> "hello from the badge"

On our bench, a text sent this way appeared on a live Meshtastic node, which added the badge as a new node and rebroadcast the message into its mesh.

// demo tip Transmitting to a node is the deterministic show — a real node's own RF can be sparse (it may be MQTT-bridged), so passively sniffing it (receive) can sit quiet for 30 s+. For a crowd, send text and point at the phone.

What we changed for the badge

If you're reading the source or forking the port, the badge-specific work lives behind -DDEVICE_RETIA_BADGE:

  • An ILI9341 TFT view (the upstream target is ST7789) driving the badge's 240×320 panel.
  • A d-pad + A/B input mapping onto the selector UI (LEFT/RIGHT move, A = OK, B = back).
  • A poll-based SX1276 LoRa driver that bit-bangs the shared SPI and hands the pins back to the display, with a bus-reacquire around every radio op so the TFT and radio don't collide.
  • On-screen bus scan + register monitor and the waterfall heat map.
  • Usable out of the box: I2C, UART, 1-Wire, DIO, LED (the ear NeoPixels), USB-HID, BLE, Wi-Fi; SPI/2WIRE/3WIRE/JTAG via SAO jumpers.
!! don't beacon with the ears Driving the 10 ear NeoPixels at high brightness on USB-only power can brown out the badge (it may latch and stop enumerating until you unplug it). Keep LED demos dim, or run them on battery.
