LoRa Leaks — Exploit a vulnerable IoT Mesh node and steal secret keys to break into a private chat

This year, ScriptKitty village and IoT Village teamed up to create this CTF, by the Retia team! Learn to use the ESP32 BitPirate your badge supports to tap into UART and i2c ports, scan networks and communicate with targets, and even use its onboard LoRa radio to break into an encrypted private chat.

DEF CON Badge Bit Pirate CTF LoRa ·intermediate·~60 min·updated 2026-08-05

The target is an IoT Meshtastic node — a Nibble Zero — set up to be vulnerable. You capture five flags, each one gives you the next. If you can spam the private chat, you win a prize at our booth!

!! authorized use only Run this against the workshop's own kit. Don't point the badge's scan, join, or transmit tools at networks, devices, or radios you weren't given. The transmit steps need a 915 MHz antenna on the badge — attach it before you send, or you can damage the radio.

0 — Put Bit Pirate on your badge

Open the flasher on the main page, pick Bit Pirate, and flash. Tap RESET and it boots to a serial CLI at 115200. Drive it from the browser terminal on the same page (Web Serial), or any serial monitor.

Flash Bit Pirate → · full CLI walkthrough: Hack LoRa & read I2C with the badge.

Anywhere in the CLI: help lists commands for the current mode, mode lists modes, ENTER stops a running command.

1 — Tap the UART and read the boot log (Flag 0)

Connect a Qwiic cable from the node's port marked UART to the Qwiic port on your badge — that taps its serial line. Then listen:

> mode uart        # ENTER through the defaults (RX 44 / TX 43 / 115200-8N1)
> autobaud         # confirm the line speed while the node talks
> snifftxt         # now power-cycle the node and read its startup chatter

The boot log tells you what you're looking at — the chip, the mesh stack, its partitions.

!! quiet tap? If snifftxt shows nothing on a power-cycle: confirm the cable is on the node's UART-marked port (not i2c), try swap, and power the node from a battery, not a laptop — a USB-powered node often sends its console to USB instead of the Qwiic line.

2 — Catch the credential leak (Flag 1)

Keep sniffing and power-cycle again. This node's factory routine prints its provisioning to the debug line every boot — a real bug class (sensitive data in logs). You'll see a block like:

==== FACTORY PROVISIONING LOG ====
[prov] uplink.ssid    = WorkshopNet
[prov] uplink.key.b64 = U2VjcmV0UGFzcw==

The network name is in the clear; the password is a short token — not the password itself. Work out what encoding it is and turn it back into the real password. That's the puzzle.

3 — Join the network and find the node (Flag 2)

> mode wifi
> scan                                   # the network from step 2 is in the list
> connect WorkshopNet <password>
> status                                 # confirm you got an IP
> nmap 10.0.0.42 -p 1-10000              # scan a range, not the default top-100
!! scan the range A bare nmap <ip> only checks the top-100 ports and can come back empty — the mesh API port is a 4-digit port that isn't on that list. Scan -p 1-10000 (or the port directly once you know the protocol).

4 — Ask the node for its channel key (Flag 3)

The node answers its own device API. From the badge you can confirm it's alive:

> http get http://10.0.0.42/api/v1/fromradio?all=true   # 200 application/x-protobuf

The channel config comes back as binary, so point a mesh client (the CLI or the phone app) at the node over the network and read its info. You're after the primary channel name and its key (PSK) — the thing that decrypts the private channel.

> meshtastic --host 10.0.0.42 --info    # channel name + PSK + the channel URL

5 — Join the private channel (Flag 4)

Load the stolen key into the badge's LoRa radio and transmit on the channel. The node is listening, and every message decrypts onto a chat wall on the room's screen.

> mode lora
> mesh
    2  -> preset  LongFast
    3  -> frequency  906.875        # US LongFast, channel 0
    4  -> channel key  <the PSK from step 4>
    6  -> send   TEAM7 we are in
!! antenna first Attach the 915 MHz antenna before send. Transmitting without one can damage the radio.

When your message lands on the wall, you've proven you can read and write a channel you were never given. First team to light up the wall (or to spam it to the target count) wins.

The same secret, a second way — over I2C (bonus)

A device that leaks over one interface usually leaks over another. This target also answers on its I2C bus like a cheap config chip. Connect a Qwiic cable from the node's port marked i2c to your badge's Qwiic port, then:

> mode i2c
> scan            # a config "chip" answers at 0x50
> dump 0x50       # the Wi-Fi password, in the clear — no network needed

Same password you decoded in step 2, pulled straight off the hardware bus — the point being that an unlocked debug UART and an open I2C port both spill the same secret. Lock one, you've still got the other.

// note — why not Bluetooth? On an ESP32, Meshtastic turns Bluetooth off whenever Wi-Fi is on — they share one 2.4 GHz radio. Since this node lives on Wi-Fi, it never advertises over BLE (you can stand right next to it and see nothing), so there's no Bluetooth way in here. A neat reminder that "enabled" features can silently disable each other.
Running the room — for instructors (spoilers & setup — click to reveal)

The node is stock mesh firmware with a "leaky provisioning" print (UART + I2C) and a known channel key. Each station gets its own channel key and Wi-Fi password from a shared seed + station number, so answers can't travel the room and a wiped station re-stamps identically. A watchdog beside the chat wall restores the channel, key, name, and Wi-Fi if a team changes them — and on tamper it flashes a red INTRUSION banner on the wall instead of healing silently. The wall also keeps a CRACKED IT leaderboard of teams in the order they first break in.

!! bench tip Use a known-good USB cable for the node. A flaky one flashes fine but silently wedges the node on small config writes — a maddening failure that looks like firmware but isn't.
